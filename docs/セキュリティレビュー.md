# セキュリティレビュー — 請求書ジェネレーター

最終実施日: 2026-07-29(公開前レビュー・第1回)
対象コミット: 初版(`public/` 一式・`vercel.json`)

## 前提となる設計

本ツールはサーバー側の処理を一切持たない静的サイトである。入力値は**利用者のブラウザ内でのみ**扱われ、
ネットワークへ送出する経路そのものが存在しない。これが最大の防御になっている。

| 項目 | 状態 |
|------|------|
| バックエンドAPI | なし |
| 外部への通信 | なし(`fetch` / `XMLHttpRequest` を一切使用しない) |
| 外部スクリプト・CDN | なし(依存パッケージ0) |
| Cookie | 使用しない |
| 保存先 | 端末の localStorage のみ |
| 認証・決済 | 未実装(有料機能は未着手) |

## 確認項目

### 1. XSS(クロスサイトスクリプティング)

`innerHTML` を使う箇所は次の4つ。それぞれ入力の出どころを確認した。

| 箇所 | 埋め込む値 | 対策 |
|------|-----------|------|
| `createItemRow` | 固定のテンプレート文字列のみ。利用者の入力は `.value` 経由で代入 | 値をHTMLに連結しない |
| `renderPreview` の明細 | 品目名・単位 | `escapeHtml()` で `& < > " '` をエスケープ |
| `renderPreview` の合計欄 | 数値のみ(`yen()` の出力) | 文字列を受け付けない |
| `renderPreview` の税率内訳 | 数値のみ | 同上 |

宛名・住所・備考など残りの自由入力欄は、すべて `textContent`(`setText()`)で描画しており、
HTMLとして解釈されない。**インラインイベントハンドラ・`eval`・`new Function` は不使用。**

### 2. コンテンツセキュリティポリシー

`vercel.json` で以下を全パスに付与する。

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:;
font-src 'self'; connect-src 'none'; form-action 'none'; base-uri 'none'; frame-ancestors 'none'
```

- `connect-src 'none'` — 万一スクリプトが混入しても、外部への送信ができない(入力内容の流出防止)
- `script-src 'self'` — インラインスクリプトを禁止。実際にインラインスクリプトは1つも使っていない
- `frame-ancestors 'none'` / `X-Frame-Options: DENY` — クリックジャッキング対策

あわせて `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、
`Permissions-Policy`(位置情報・マイク・カメラを無効化)を付与している。

### 3. 外部から取り込むデータ

「JSONを読み込む」機能は利用者自身が選んだファイルを読む。悪意あるJSONを読ませられた場合を想定し、

- 値はすべて `.value` またはエスケープ済みの描画経路に流れる(スクリプトにならない)
- `docType` は `hasOwnProperty` で既知のキーのみ採用し、未知の値は「請求書」に落とす
- パース失敗時は例外を捕捉してメッセージを出すだけで、処理を継続しない

### 4. 保存データの取り扱い

- 下書きは localStorage の `invoice-tool:draft:v1` にのみ保存される
- 「入力をすべて消す」で削除できる。この動作は `/legal.html` に明記した
- 共用端末での注意喚起も同ページに記載
- localStorage が使えない環境(プライベートブラウズ等)でも例外を捕捉し、機能は継続する

### 5. 依存関係

外部パッケージを使用していないため、サプライチェーン経由の脆弱混入の経路がない。

## 残課題(有料機能の実装前に必ず再レビューする)

1. **Stripe組込み時**: 決済ページでは `connect-src` に Stripe のエンドポイントを追加する必要があり、
   `script-src` も緩める判断が要る。CSPを決済ページ限定で分離すること。
2. **サーバー保存機能(取引先マスタ・発行履歴)を作る場合**: 取引先名・金額という機微情報を
   預かることになる。現在の「サーバーに何も送らない」という約束と `/legal.html` の記載を
   必ず同時に見直す。端末内保存で完結できる設計を優先して検討する。
3. **広告を導入する場合**: 第三者スクリプトの読み込みはCSPの緩和を伴う。導入可否は
   「入力内容が第三者に渡らないこと」を条件に判断する。

## 結論

現時点の実装(静的サイト・外部通信なし・決済なし)について、公開を妨げる問題は確認されなかった。
ただし**本番公開はオーナー承認後**に行う。
