# 請求書ジェネレーター — 機能仕様

事業B4「日本語ニッチWebツール群」の2号(候補リスト20.md #1)。

## 1. 課金方針(オーナー承認済み 2026-07-27)

書籍K1『請求書&インボイス実務』第6章で「無料プランでPDFに透かしが入るツールは取引先への送付に向かない」と
書いたため、**自著で批判した仕様を自社ツールが持つ状態を避ける**。

- **無料プランでも、出力するPDFは取引先にそのまま送れる完成品とする**(透かし・ロゴ・広告の埋め込みなし)
- 課金は「1通作るのに必要な機能」ではなく、**「何度も作る人の手間を減らす機能」**から取る

| # | 有料機能 | 状態 |
|---|----------|------|
| 1 | 取引先・品目マスタの保存 | 未着手 |
| 2 | 有料テンプレート(英文・源泉徴収欄あり等) | 未着手 |
| 3 | 見積書 → 納品書 → 請求書 の変換 | 未着手(書類種別の切替のみ実装済み) |
| 4 | 連番の自動採番と発行履歴の一覧 | 未着手 |

この方針は候補リスト #3(見積書)・#6(領収書)にも適用する。

## 2. K1第6章のチェックポイント(出版前チェックリスト E1〜E6)への対応

書籍で「ツール選びのチェックポイント」として挙げた6項目を、自社ツールが満たしていることを確認する。

| # | チェック項目 | 対応状況 |
|---|-------------|---------|
| E1 | 適格請求書の記載事項を満たせる(登録番号欄・税率ごとの区分集計) | **対応済**。登録番号欄(形式検証つき)と「税率ごとの内訳」表を用紙に常時出力 |
| E2 | 消費税の端数処理を選べる | **対応済**。切り捨て / 四捨五入 / 切り上げから選択。既定は切り捨て |
| E3 | 源泉徴収に対応している | **対応済**。10.21% / 20.42%、税抜・税込の対象選択、行単位の対象外指定 |
| E4 | PDFに透かしが入らない | **対応済**。透かし・ロゴ・広告を一切入れない(上記1の方針) |
| E5 | データを書き出せる(CSV等) | **対応済**。CSV(UTF-8 BOM付き・Excel対応)と JSON |
| E6 | 保存データの所在が明確 | **対応済**。ブラウザ内完結である旨を画面と `/legal.html` に明記 |

## 3. 計算仕様

### 消費税

- 税率は 10% / 8%(軽減)/ 非課税 から行ごとに選択する
- **端数処理は「一の請求書につき、税率ごとに1回」**行う。明細行ごとの端数処理は行わない(国税庁 No.6625)
- 処理方法は請求書全体で1つを選ぶ(切り捨て / 四捨五入 / 切り上げ)

### 源泉徴収(国税庁 No.2795)

```
支払金額 100万円以下 : 支払金額 × 10.21%
支払金額 100万円超   : (支払金額 - 100万円) × 20.42% + 102,100円
```

- 1円未満は切り捨てる
- 報酬額と消費税額を明確に区分している場合、対象は**税抜金額**(既定)。区分しない場合は税込金額を選べる
- 物品代・立替実費など対象外の明細は、行単位でチェックを外して除外できる
- **源泉徴収の要否そのもの(職種の判定)はツールでは判断しない。** 利用者が選択する

### 登録番号

- 「T + 数字13桁」の形式のみ検証する。**実在確認は行わない**(国税庁の公表サイトで確認するよう画面で案内)
- 未入力でも書類は作成できる(免税事業者向け)。その場合は適格請求書として扱えない旨を案内する

## 4. 出力

| 形式 | 方法 | 備考 |
|------|------|------|
| PDF | ブラウザの印刷ダイアログ(`window.print()`) | A4縦1ページに収まるようレイアウト済み。日本語フォントの埋め込み問題を回避できる |
| CSV | Blobダウンロード | UTF-8 BOM付き。Excelで文字化けしない |

## 5. 集客の導線(2026-07-30 追加)

**ツールは作っただけでは見つからない。** 検索の入口になる解説記事を、ツールと同じドメイン配下に置く。

| URL | 狙う検索意図 | ツールへの出口 |
|-----|-------------|--------------|
| `/` | 「請求書 作成 無料」「請求書 テンプレート」 | 本体 |
| `/guide/seikyusho-kakikata` | 「請求書 書き方」「請求書 必須項目」「インボイス 記載事項」 | 記事内に2箇所のCTA |
| `/guide/gensen-choshu-keisan` | 「源泉徴収 計算」「10.21% 計算方法」「源泉徴収 税抜 税込」 | 同上 |
| `/mitsumorisho` | 「見積書 テンプレート」「見積書 有効期限」「見積書 ただし書き」 | `/?type=estimate` |
| `/inshi` | 「収入印紙 いくら」「領収書 印紙」「収入印紙 金額」 | `/?type=receipt` |
| `/guide/` | 回遊用のハブ | 各記事へ |

設計上の決めごと:

- **書類種別はURLで指定できる**(`/?type=invoice|estimate|delivery|receipt`)。
  ランディングから遷移した時点で正しい種別が選ばれている状態にする。
  値は既知のキーとの完全一致でしか採用しない(セキュリティレビュー 第2回)
- **記事の内容はK1『請求書&インボイス実務』と同じ数値・同じ結論に揃える。**
  書籍とツールで記述が食い違うと、どちらの信用も落ちる。計算例は書籍第4章の検算済みの値を使う
- **外部サイトへのリンクは張らない。** 制度の出典はタックスアンサーの番号と名称のみを本文に記載する
  (存在しないURLを書かない方針)
- **sitemap.xml は本番ドメインが確定してから作る。** 絶対URLが必須のため、先に仮のURLを書かない

## 5-2. 収入印紙 判定ツール(`/inshi`・2026-07-31 追加)

領収書=**第17号文書の1(売上代金に係る金銭又は有価証券の受取書)**の印紙税を判定する。
判定ロジックは `public/stamp.js`(DOMに依存しない純粋関数)、画面制御は `public/inshi.js`。

### 判定の順序(順序そのものが仕様)

1. **電子データで交付** → 不要(紙の課税文書を作っていない)
2. **営業に関しない受取書** → 非課税(自由職業者・私物の売却など)
3. **クレジットカード利用を明記** → 不要(その場で金銭を受領していない)
4. 上記以外 → **記載金額**を決めて税額表を引く

### 記載金額の決め方(ここが競合と差がつく点)

| 発行者 | 消費税額を金額で区分記載 | 印紙税の記載金額 |
|--------|------------------------|----------------|
| 課税事業者 | する | **税抜金額**(消費税額を含めない・No.7124) |
| 課税事業者 | しない | 税込の総額 |
| **免税事業者** | する / しない のどちらでも | **税込の総額**(区分記載の取扱いを使えない) |

**免税事業者の扱いはK1第3章の最重要論点**で、同じ書き方でも課税事業者と結論が変わる。
`tests/stamp.test.js` で、税抜48,000円・消費税4,800円のときに
**課税事業者=印紙不要 / 免税事業者=200円**となることを固定している。

### 出典と検証状況

| 内容 | 出典 | 状態 |
|------|------|------|
| 税額表(全15区分) | 国税庁 No.7141 | **原文で全区分を照合済み(2026-07-31)** |
| 5万円未満は非課税 / 営業に関しない受取書は非課税 | 国税庁 No.7105 | **原文で確認済み(2026-07-31)** |
| 消費税額の区分記載は記載金額に含めない | 国税庁 No.7124 | 番号・名称のみ本文に記載 |
| **電子交付で不要 / クレジットカード明記で不要** | — | **一次資料に到達できず未確認。** 判定結果に注意書きを必ず添える実装にしている |

### 請求書ジェネレーターとの連携

書類の種類が「領収書」のときだけ、入力画面に `/inshi?amount=<税抜合計>&rate=<税率>` への
導線を出す(`app.js` の `updateStampHint()`)。金額を入力し直さずに判定へ渡せる。
税率が混在する場合は高いほうを既定にする(印紙が過小に出ないようにするため)。

## 6. 実装しないと決めたこと(判断の記録)

- **PDF生成ライブラリ(jsPDF等)は使わない。** 日本語を出すには数MBのフォント埋め込みが必要で、
  初期費用0円・依存0の方針に反する。ブラウザの印刷機能で同等のPDFが得られる
- **サーバー側の保存機能は現時点で作らない。** 取引先名と金額という機微情報を預かる責任が発生する。
  有料機能の実装時に、端末内保存で完結できないか改めて検討する(セキュリティレビュー 残課題2)
- **アクセス解析・広告は未導入。** 導入する場合は `/legal.html` に取得情報を明記してから行う
